Validation

Two checks back the atlas: the population simulation layer was compared with an established open-source tool, and every model was implemented a second time from its paper alone, with separate code, and compared with the atlas implementation. Both checks were made within this project; none has yet been made by outside people.

Simulation layer against mrgsolve

The dosing and population machinery was run against mrgsolve 2.0.1 (R) on identical models, doses and time grids, with tight solver tolerances on both sides (2026-11-04). The scripts are in validation/mrgsolve/.

Dose control with random effects and between-occasion variability

A one-compartment model with first-order absorption, bioavailability F = 0.6 exp(ηF) WT / 70 and lag ALAG = 0.75 exp(ηLAG) on the depot (computed by the model's dosecontrol), and clearance CL = 2 exp(κ) with κ of the occasion (OCC column, NOCB; mrgsolve selects κ by OCC in $MAIN, the NONMEM indicator-variable way), 2026-11-05. In the exact case every subject has SUPPLIED η and κ values (data set columns in mrgsolve, η and κ arguments in QSPAtlas), so individual curves are compared record by record; in the distribution case both tools draw their own random effects.

The same features are tested against closed forms in test/iov.jl (log-normal AUC under log-normal F, the lag distribution, covariance and independence of the κ draws, exact switching at occasion boundaries).

For the population case both tools were also compared with a near-exact reference (closed form, 4 million draws). QSPAtlas sampling with one million draws matches the reference to 1.7e-3 (largest z-score 1.96).

Differences in convention, documented in Population simulation:

  • Where steady state starts. QSPAtlas iterates dosing cycles from the model's initial conditions, mrgsolve from the state at the steady-state record. QSPAtlas and mrgsolve agree on every steady-state case above; they can differ for models with several periodic solutions or slow, history-dependent states. How NONMEM initialises its steady-state computation depends on the routine and was not compared with NONMEM output here.
  • Observations at a dose time see the state after the dose (mrgsolve recsort = 3) unless tagged :pre; datasets set the tag from the record order, and ADDL doses come before an observation at the same time (mrgsolve's default; not checked against NONMEM).
  • LOCF covariates. With nocb = FALSE, mrgsolve evaluates the output of a record with the previous record's covariates (the record's own values start after it); QSPAtlas uses the record's values at the record. The states agree; an output that depends on the covariate (here the concentration, through the volume) differs at the change records. NOCB is the convention the NONMEM documentation describes; under NOCB QSPAtlas and mrgsolve agree.
  • SS=2 with an endogenous baseline. mrgsolve adds the whole steady state of the SS=2 dose, including the turnover response's own baseline (the response jumps from 100 to 200 with no drug effect when IMAX = 0). QSPAtlas adds the periodic state minus the dose-free periodic state, so the baseline is not counted twice. For PK compartments starting at zero the two are the same and agree to 6e-9.
  • Steady-state constant infusion. The infusion ends at the record (NONMEM Users Guide); mrgsolve 2.0.1 behaves the same, although its user guide describes the infusion as never-ending.
  • SS=1 after a record with ADDL doses. QSPAtlas cancels the ADDL doses of earlier records that are still to come at the SS=1 time, as the NONMEM help on SS describes ("infusions in progress or pending additional doses are cancelled"); not compared with NONMEM output. mrgsolve 2.0.1 stops the running infusion but keeps the later ADDL doses: its output agrees to 7.0e-10 with QSPAtlas run with those doses written as dose records of their own (case d8_ss_addl, ss_addl_qspatlas.jl and ss_addl_mrgsolve.R). QSPAtlas on the dataset and QSPAtlas with the cancelled doses left out by hand agree exactly.
  • A reset cancels lagged doses that have not yet been given and keeps later addl doses.
  • A lagged dose entering exactly at an observation time. QSPAtlas reports the state after the dose (as for any dose at an observation time); mrgsolve 2.0.1 reports the state before it. Found while setting up the IOV cases (a lag of exactly 0.75 h on a 0.75 h observation); the cases above use lags that do not coincide with observation times.

Third implementation from the authors' own code

For four models the authors published their NONMEM or Monolix code. That code was translated to rxode2 (R) with nonmem2rx and monolix2rx (or by hand where the code is printed in a PDF), run with the parameter values and inputs the atlas uses (the code often carries initial estimates, so this checks equations, structure, dosing and units, not the values), and compared point by point with the atlas. Scripts: validation/authors_code/.

Differences between the code and the paper that this check exposed (none affects an atlas target): in Ouerdani's code a control run (DOSE = 0) switches all drug terms off, while the paper's Eq. 2 with beta_alpha = 0 keeps alpha = alpha0 for any exposure; in Hutchinson's code the normalisation factor is N = Nmax x dose + 1, not Eq. 5's Nmax; Hutchinson's Figure 6 chemotherapy is not in the code. Stroh and Fornari published no runnable code (Stroh's supplement has the reaction matrices, checked entry by entry; Fornari's code is truncated).

Second implementations of the six models

Each model was implemented a second time from its paper and supplement alone, without access to the atlas code, in plain OrdinaryDiffEq without ModelingToolkit, within this project. The second implementation made its own choices for every unstated input. It compared simulations only: nothing was re-digitised, so digitising errors are not covered by this check. Where both implementations chose an unstated input (a dose group, a starting value) by matching the figure, their agreement is not independent evidence for that choice. Results:
